## 言語

- 応答・説明・PR本文: 日本語
- コミットメッセージ・PRタイトル: 英語（Semantic Commit Messages形式）
- コードコメント: 必要最小限。コードの自己文書化を優先する

## ルール追加プロセス

今回限りでなく常に適用すべき指示を受けた場合:

1. 「これを標準のルールにしますか？」と質問する
2. YESなら適用範囲を判断して記載先を選ぶ:
   - 全プロジェクト共通 → `~/.claude/CLAUDE.md`（トピックが独立するなら `~/.claude/rules/` の該当ファイル）
   - プロジェクト固有 → そのリポジトリのCLAUDE.md
3. 操作の確実な禁止が目的の場合は、CLAUDE.mdへの記載ではなくPreToolUse hookの追加を提案する

## 作業の進め方

- 実装前に関連ファイルと既存の規約・パターンを確認してから着手する
- 複数ステップのタスクはTodoWriteで分割・管理する
- 実装後はビルド・型チェック・リンター・既存テストを実行して確認する
- ビルド/テストの失敗を3回修正しても解決しない場合は、現状と困っている点を報告してユーザーに相談する
- 設計上の選択肢がある場合は、理由を添えて提案し、判断が必要な点は質問する
- 主要なステップごとに進捗を報告する

## ツール使用方針

- GitHub操作: GitHub MCPツール（`mcp_`で始まるツール）が利用可能な場合は`gh`コマンドより優先する
- Web検索: MCP提供のWebツールが利用可能な場合は通常のWebFetchツールより優先する
- ローカルサーバー操作: devtools MCPを使う
