# コーディング規約（言語共通）

## ファイル・モジュール設計

- 1ファイル100行程度を目安とし、最大でも200行を超えない
- 単一責任の原則に従う。5つ以上の責務を持つクラス、God Object、3階層以上の深い継承は避ける
- rootディレクトリにむやみにファイルを増やさず、必要最小限に留める
- 200行を超えるファイルの分割は段階的に行い、各ステップでビルドとテストを実行して機能が保持されることを確認する。循環依存を避ける

## 命名

- 一時的・段階的な改善を示すプレフィックス/サフィックス（`New` / `Old` / `Temp` / `V2` / `Final` / `Optimized` / `Ultimate` 等）は絶対に使用しない。リファクタリング完了後の最終的な名前を直接使い、バージョン管理はGitに任せる
- ファイル名・クラス名・関数名は役割を明確に表すものにする
- プロジェクト内で同じ概念には同じ命名パターンを使用する

## 実装

- mock/stubの使用はテストコード限定。実装コードでの使用は禁止する
- 不要なコメントは一切残さない。コードの自己文書化を心がける
